## Code of Conduct

This project is committed to providing a welcoming and respectful environment for everyone.

By participating, you agree to:

- Be respectful and constructive in discussions
- Use inclusive and professional language
- Accept constructive feedback gracefully
- Focus on improving the project rather than winning arguments
- Assume good intent from other contributors

Harassment, discrimination, or aggressive behavior will not be tolerated.

---

## Project Scope

**qddd** focuses on:

- Domain-Driven Design concepts
- Architectural patterns and boundaries
- Code quality, modeling clarity, and explicit design
- Educational and exploratory use cases

Contributions should align with these goals.  
Features that add complexity without clear architectural or learning value may be declined.

## How Can I Contribute?

### Reporting Bugs

If you find a bug:

- Use the GitHub issue tracker
- Use a clear and descriptive title
- Describe the expected behavior vs the actual behavior
- Provide steps to reproduce the issue
- Include environment details if relevant (OS, language/runtime version, etc.)
- Attach logs, stack traces, or minimal repro examples when possible

### Suggesting Enhancements

Enhancement ideas are welcome:

- Open an issue with the `enhancement` label
- Clearly describe the problem you are trying to solve
- Explain why the change fits the goals of qddd
- Provide examples, diagrams, or pseudo-code if helpful
- Be open to discussion and alternative solutions

### Pull Requests

You can contribute code by submitting pull requests:

1. Fork the repository
2. Create a new branch (`git checkout -b feature/my-feature`)
3. Make your changes following the coding and design guidelines
4. Add or update tests if applicable
5. Update documentation when needed
6. Commit your changes with clear messages
7. Push your branch and open a Pull Request
